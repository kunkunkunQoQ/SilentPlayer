# SilentPlayer

极简、静默、低资源占用的 Windows 音频播放器。

**打开音频 → 自动播放 → 隐藏 → 托盘驻留。**

SilentPlayer 不是传统音乐播放器，也不是音乐库或 Soundboard。它只做一件事：把音频文件静默地播放出来。平时你完全看不到它，只有点击系统托盘图标后，才显示一个非常简单的播放控制窗口。

## 核心功能

- 打开音频文件后**自动播放**（命令行 / 打开方式 / **把文件拖到播放器窗口**）
- 默认**不显示任何窗口**，只在系统托盘后台运行
- 托盘图标左键单击：显示播放器窗口
- 托盘图标右键菜单：播放/暂停、停止、销毁、显示播放器、退出
- 播放器窗口（逻辑尺寸 420 × 222，按显示器 DPI 缩放）：文件名、状态、播放进度、当前时间、总时长、播放/暂停、停止、销毁、音量
- 窗口布局按行分区，互不挤压：文件名 → 状态 → 进度条 → 当前时间/总时长（左右对齐）→ 居中按钮 → 音量
- 播放进度可拖动
- **停止 ≠ 销毁**：停止只停播放、保留当前文件信息（状态显示「已停止」）；
  **销毁**会停止并彻底释放媒体、清空文件名与时间，回到「未打开文件」的空闲状态（进程与托盘继续运行）
- 播放结束后**自动清理**：与「销毁」走同一条清理路径，释放媒体资源、清空文件名、
  状态回到「未打开文件」、进度与时间归零，并继续驻留托盘，**不自动播放下一首**
- **单实例**：再次打开新的音频文件时，由已运行实例接管并切换播放，不会出现第二个进程
- **支持把文件拖到播放器窗口上直接播放**（拖入时显示"复制"光标；多文件只播第一个）
- 关闭播放器窗口 = 隐藏窗口并继续后台播放；托盘菜单「退出」才真正结束程序
- 不保存播放列表、不保存播放历史、不保存播放状态
- 带标准 Windows 版本资源：任务管理器「进程」页显示名为 **SilentPlayer**，映像名 `SilentPlayer.exe`

## 支持格式

全部使用 Windows 自带的 Media Foundation 解码，**不需要任何第三方库，也不需要转码**。

| 格式 | 说明 |
| ---- | ---- |
| MP3 | 原生解码 |
| WAV | 原生解码 |
| MP4 | **只播放其中的音频轨道**，不显示视频、不需要转码 |
| M4A | AAC 音频 |
| AAC | ADTS 容器 |
| FLAC | 原生无损解码 |
| WMA | 原生解码 |
| 其他 | 理论上凡 Media Foundation 能解析的音频容器/编码都可用（如 ALAC、AC3/EAC3、AMR 等） |

**格式按文件内容识别，不信任扩展名。** 即使把 `music.mp4` 改名成 `music.mp3`
（或反向），只要 Media Foundation 能识别其中的音频，就照常播放：

- 读取文件头判断真实容器，再把 MIME 类型交给 Media Foundation 解析
- 扩展名只作为识别不出内容时的兜底
- **不会修改原文件**、不会转码、不会产生临时文件

实测格式矩阵与验证方法见 [docs/CHANGELOG.md](docs/CHANGELOG.md)。

## 使用方法

### 直接运行

双击 `SilentPlayer.exe`：程序驻留托盘，不显示任何窗口。

### 打开音频文件（自动播放）

```
SilentPlayer.exe music.mp3
```

或通过「打开方式」选择 SilentPlayer 打开音频文件。

重复执行时（例如再次打开 `music2.mp3`）：

```
SilentPlayer.exe music2.mp3
```

已运行的实例会停止当前播放、切换并自动播放 `music2.mp3`，不会启动第二个进程。

### 显示播放器

点击系统托盘中的 SilentPlayer 图标（左键），即可看到播放控制窗口。关闭窗口后播放继续，程序仍驻留托盘。

## 系统要求

| 运行环境 | 说明 |
| ---- | ---- |
| Windows x64 | 原生运行 |
| Windows 11 on ARM64 | 由系统内置的 x64 模拟层运行，无需另装版本 |
| Windows 10 on ARM64 | 不支持（该系统只提供 x86 模拟，不提供 x64 模拟） |

- 无需安装 .NET / Java / Python / 任何运行环境
- 无需任何第三方库

## 下载 / 运行方式

发布产物为**单个可执行文件**：`SilentPlayer.exe`（Release 构建，约 267 KB）。

**x64 Windows 与 Windows 11 on ARM64 使用同一个文件**，不需要按 CPU 架构选择版本，
也不存在 `-x64` / `-arm64` 之类的分支文件。

直接复制到任意目录双击即可运行，无安装程序、无后台服务、无附加文件。

> 关于单 EXE 双架构的实现方式（为什么 x64 产物在 ARM64 上可用、为什么不使用 ARM64EC）
> 见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

## 默认行为

- 音频默认输出到 **Windows 当前默认播放设备**（不修改系统默认设备）
- 音量默认 80%（仅本次运行有效，重启后恢复默认），音量滑块实时作用于音频会话
- 播放结束：停止并驻留托盘
- 不自动恢复上次播放的歌曲、进度或列表
