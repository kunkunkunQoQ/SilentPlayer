## A. 极低成本（≤ 约 30 行，不动架构、不加依赖）—— ✅ 已全部实现（见 CHANGELOG）

### A1. ✅ 托盘悬停显示当前播放内容

- **做什么**：鼠标悬停托盘图标时，提示文字从 `SilentPlayer` 变成 `SilentPlayer — 歌名`。
- **为什么顺手**：`TrayIcon::SetTooltip()` **已经实现好了，但全项目 0 个调用点**（现成挂点）。
- **改动面**：`App::LoadFile` / `App::ResetToIdle` 各加一次调用 + 拼字符串。
- **风险**：极低（`NIM_MODIFY` 逻辑已在 `TrayIcon` 内）。
- **验证**：`player_state_probe --traydump` 取不到 tooltip，需要新增一个读 tooltip 的探针模式（或用 UI 自动化读）。

### A2. ✅ 副标题显示当前输出模式

- **做什么**：开启「输出到麦克风」时，副标题显示「正在播放 · 输出到麦克风」。
- **为什么顺手**：副标题已有 4 种状态与 8 个 `SetStatus` 调用点，只需在拼串时带上模式。
- **改动面**：`App` 里集中一处拼状态文本（**建议先把 8 处调用收敛成一个私有 `UpdateStatusText()`**，否则容易漏）。
- **风险**：低。
- **验证**：`player_state_probe` 读 `IDC_SUBTITLE` 文本。

### A3. ✅ 鼠标滚轮调音量

- **做什么**：窗口上滚轮 → 音量 ±5%。
- **为什么顺手**：`WM_MOUSEWHEEL` **当前完全未处理**；音量滑块与 `SetVolumeUI` 同步逻辑已存在。
- **改动面**：`PlayerWindow::HandleMessage` 加一个 case → 调 `App::SetVolume()`。
- **风险**：低。
- **验证**：`player_state_probe --volume=i:v` 已有同类校验路径。

### A4. ✅ 键盘操作：空格暂停、左右箭头快退/快进

- **做什么**：空格 = 播放/暂停，←/→ = 退/进 5 秒。
- **为什么顺手**：`WM_KEYDOWN` 未处理；`TogglePlayPause()` / `SeekToFraction()` 都已就绪。
- **改动面**：一个 case + 让窗口能获得焦点（现在主窗口默认不抢焦点）。
- **风险**：低。
- **验证**：`player_state_probe --toggle` / `--seek` 已有等价校验。

### A5. ✅ 托盘菜单顶部显示当前文件名

- **做什么**：菜单第一行以灰色禁用项显示正在播放的文件名。
- **为什么顺手**：`ShowTrayMenu` 的菜单构建逻辑就在手边（现有 8 项）。
- **改动面**：2 行（`MF_STRING | MF_GRAYED | MF_DISABLED`）。
- **风险**：极低。
- **验证**：`--traydump` 直接可读（现有能力）。

### A6. ✅ 命令行 / IPC 支持控制命令

- **做什么**：`SilentPlayer.exe --toggle` / `--stop` / `--volume=50`，由已运行实例执行（可给脚本、Stream Deck 用）。
- **为什么顺手**：单实例转发通道（`WM_COPYDATA`）已存在，`App` 已有 `TogglePlayPause/Stop/SetVolume` 等命令入口。
- **改动面**：`main.cpp` 参数解析 + `PlayerWindow.cpp:613` 的 `WM_COPYDATA` 分支 + `App` 一个小分发函数。
- **风险**：低，但**必须保证不破坏现有语义**（负载是"文件路径"）。
- **验证**：`SingleInstance` 路径已有探针可复用。

### A7. ✅ 首次关闭窗口时提示"已最小化到托盘"

- **做什么**：第一次点关闭时给一次性提示，避免用户以为程序退出了。
- **为什么顺手**：`WM_CLOSE` 已有（隐藏窗口）。
- **改动面**：小（一个静态标志 + 一次提示）。
- **风险**：低。**注意与项目原则"默认静默、无 Toast"冲突**，需要你确认。
- **验证**：探针读副标题/状态。

## B. 中等（几十~上百行，需少量新逻辑，仍无新依赖）

### B1. 单曲循环 / 同目录顺序播放

- **做什么**：播放结束后自动重播或播同目录下一首。
- **为什么顺手**：结束路径已收敛（`MESessionEnded` → `DestroyMedia()`），改成分支即可。
- **需要新增**：同目录枚举（`FindFirstFile`）、一个播放模式状态、`App::PlayNext()`。
- **风险**：**中**。涉及媒体生命周期，必须复用 `DestroyMedia()` + `ReloadMedia()`，不要写出第二套清理。
- **⚠ 与现有定位冲突**：当前设计明确写了"**不自动播放下一首**"。要做得作为**可选开关**，需要你先确认。
- **附带**：`上一首/下一首` 按钮 —— 按钮行已排满 3 个（`3×84 + 2×20 = 292`，内容区 384），加两个按钮需要重排布局或缩小按钮。

### B2. 显示媒体标题 / 艺术家（读元数据）

- **做什么**：文件名位置优先显示 `Title`，副标题显示 `Artist`；没有标签就回退文件名。
- **为什么顺手**：MF 的呈现描述符在 `BuildTopology` 阶段本来就拿得到。
- **需要新增**：读 `PKEY_Title` / `PKEY_Music_Artist`（约 40 行）+ 事件把字符串带给 UI。
- **现状**：**当前完全没有读元数据**（`GetPresentationDescriptor` / `IMFMetadata` / `PKEY_*` 全项目 0 处）。
- **风险**：低-中（很多文件没有标签，回退逻辑要写对）。
- **验证**：用带/不带标签的样本各测一次。

### B3. 播放速度 0.5× ~ 2×

- **做什么**：变速播放（听播客/学习有用）。
- **为什么顺手**：会话对象已在手（`m_session`），QI 到 `IMFRateControl` 即可。
- **现状**：**当前未涉及限速**（`IMFRateControl` / `IMFRateSupport` 0 处）。
- **需要新增**：QI + `SetRate` + UI（菜单项或滑块）。
- **风险**：中（部分解码器不支持限速，必须处理失败并回退，不能静默失效）。
- **验证**：变速后用 `audio_loopback_probe` 测仍在出声 + 进度推进速度变化。

### B4. 托盘图标随状态变化

- **做什么**：播放中/空闲用不同图标。
- **为什么顺手**：`TrayIcon` 已持有 `HICON`，且 `SetTooltip` 已经在走 `NIM_MODIFY`。
- **需要新增**：`resources/resource.h` 目前只有 `IDI_APP 101` → 要加一个图标资源 + 一个 `SetIcon`。
- **风险**：低（需要你提供或确认第二个图标）。
- **验证**：`--traydump` 读不到图标，需要截图或读 `NOTIFYICONDATA`。

### B5. 记住窗口位置

- **做什么**：下次启动回到上次的位置。
- **为什么顺手**：居中逻辑已集中在一处（`Create`）。
- **需要新增**：持久化（见 D2 —— 当前项目**没有任何配置存储**）。
- **风险**：低，但会引入"状态持久化"这一新概念。

### B6. 音频设备热插拔处理

- **做什么**：默认设备被拔出时提示或自动切回。
- **为什么顺手**：`WM_DEVICECHANGE` / `IMMNotificationClient` 当前都未使用，接口干净。
- **需要新增**：通知客户端注册与注销（生命周期要管好，避免泄漏）。
- **风险**：中。

## D. 不建议做（与定位/约束冲突）

| 项 | 原因 |
| --- | --- |
| 播放列表 / 音乐库 / 搜索 | 定位是"单文件静默播放器"，不是音乐库 |
| 播放状态 / 音量持久化 | 现有明确原则"不保存播放状态"（音量仅内存、重启回 80%）。要做属于**改定位**，不是顺手加 |
| 均衡器 / 音效 | 需要 APO 或 MF 变换链，超出"无第三方"的简易边界 |
| 拖到托盘图标 | Windows 层面不可行（已实测取证） |
| 直接"写进麦克风" | 需内核态驱动（已实测不可行；现用按应用音频路由替代） |
| 媒体库索引 / 封面墙 | 同"播放列表" |

### T1. ✅ 已实现：托盘菜单加「打开文件…」——**最高价值** ✅ 依据：源码事实

- **问题**：全项目**没有任何文件选择对话框**（`IFileOpenDialog` / `GetOpenFileName` / `OPENFILENAME` 均 0 处）。
  打开文件只有三条路：命令行参数、**把文件拖到窗口上**、双击文件（系统关联）。
  对一个"平时窗口是隐藏的"托盘程序来说，**用户没有任何可发现的入口去挑一个文件**——
  窗口隐藏时连拖放都做不到。
- **改动面**：托盘菜单加一项 + `IFileOpenDialog`（~40 行，纯系统 API，无新依赖）。
- **风险**：低（新增入口，不动现有路径）。
- **验证**：菜单项出现、选文件后开始播放（探针可读状态）。

### T2. ✅ 已实现：滚轮统一在整窗调音量，且**不要在进度条上误改播放位置** ✅ 依据：源码 + trackbar 既定行为

- **问题**：`WM_MOUSEWHEEL` 只在主窗口的 WndProc 处理。光标落在子控件上时由子控件接收：
  - 音量条：trackbar 自己处理 → 音量变化（结果正确）；
  - **进度条：trackbar 自己处理 → 按 `TBM_SETLINESIZE=20`（2% ≈ 2.4 秒）跳播放位置**（用户只是想调音量！）；
  - 按钮：忽略 → 什么都不发生。
- **改动面**：在进度条子类化里把 `WM_MOUSEWHEEL` 转发给父窗口（~5 行）；按钮同理可选。
- **风险**：低。
- **验证**：`--wheel` 后看音量是否变、进度是否不动。

### T3. ✅ 已实现：音量滑块也支持"点哪跳哪" ✅ 依据：源码事实

- **问题**：进度条已做点击跳转（N2），**音量条没做** → 同一个窗口里两种手感不一致。
- **改动面**：复用进度条那套子类化模式（~10 行）。
- **风险**：低。

### T4. ✅ 已实现：长文件名悬停显示完整名 ✅ 依据：源码事实

- **问题**：文件名用 `SS_ENDELLIPSIS` 截断，而**全项目 0 个 tooltip 控件** → 截断后没有任何办法看到完整名。
- **改动面**：给文件名标签加一个 tooltip 控件（~20 行）。
- **风险**：低。

### T5. ✅ 已实现：退出时清理按应用路由 ✅ 依据：源码事实

- **问题**：`ClearProcessOutputDevice` 只在启动/切换时调用，**退出时不清** →
  开着「输出到麦克风」退出会在系统里留下持久化设置（下次启动会自愈，但"不留痕迹"更干净）。
- **改动面**：`App::ExitApp` 加一次清除（~2 行）。
- **风险**：极低。

### T6. ✅ 已实现：高对比度适配 ✅ 依据：源码事实

- **问题**：副标题/时间/百分比的灰色是**硬编码** `RGB(110,110,110)`（`PlayerWindow.cpp:723`），
  高对比度主题下可能不可读。
- **改动面**：改用 `GetSysColor(COLOR_GRAYTEXT)`（~1 行）。
- **风险**：极低。

### T7. 键盘可达性（Tab 切换控件）✅ 依据：源码事实

- **问题**：完全没有 Tab 处理（`IsDialogMessage` / `WS_TABSTOP` / `WS_EX_CONTROLPARENT` 均 0 处）→
  键盘用户在控件之间切不过去（只能靠空格/箭头这些全局快捷键）。
- **改动面**：消息循环加 `IsDialogMessage` + 给控件加 `WS_TABSTOP`（~20 行）。
- **风险**：中（要小心不要和"消息循环里拦截快捷键"打架）。
- **建议**：除非确实需要键盘操作，否则优先级低于 T1。

### T8/T9. ✅ 已实现：两处小瑕疵 ✅ 依据：源码事实
