- [ ] 反复切换「输出到麦克风」的资源增长（实测约 **+1MB / +9 句柄每次**）

    因此增长更可能来自**每次的弹窗 + 托盘菜单**这类 UI 对象；日常使用（几次切换）无影响。
  - **后续方向**：把 ON 的弹窗改成只在第一次开启时提示，之后不再弹；再复测确认。

    或 `AA64 (ARM64)`；两者**都无法在 x64 Windows 上运行**，只能作为可选加速版本单独分发。
- [ ] 句柄缓慢增长（约 +2/次，修复前 +18/次）
  - **测试条件**：连续 20 / 40 次打开同一文件（`SilentPlayer.exe t.mp3` 反复启动第二实例），
    静置 6 秒后用 `proc_mem_probe` 采样：409 → 453（+2.2/次）→ 491（+1.9/次）。
    播放→销毁 ×10：457 → 487（+3/轮，静置后 477）。工作集始终封顶（31~33 MB）。
  - **已排除**：纯 IPC 路径（0）、会话创建/销毁 ×20（0，249→249）、只 resolve（0）、
    只建拓扑（0）、同一拓扑反复 Start/Stop（≈0）。
  - **结论**：增长来自「每次 `SetTopology` 新拓扑被会话累积」（不重建会话时约 +13/次）；
    会话重建已消除绝大部分，残留约 2 个/次在媒体加载路径内部。
  - **是否影响长时间正常使用**：不影响。按 +2/次计，连续打开 1000 个文件约 +2000 句柄，
    远低于进程句柄上限，内存也不增长。

    不建议为追求 0 增长而改动会话/拓扑架构。
